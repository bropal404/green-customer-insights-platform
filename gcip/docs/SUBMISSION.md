# Where each hand-in item is

The brief's nine items (A-I). Paths are relative to `gcip/`. The final report is `deliverables/final_report.pdf` at the
repository root.

| | Item | Where |
|---|---|---|
| A | Working prototype | `./run.sh`: the staff dashboard at http://localhost:8050 and the customer app at http://localhost:8050/app/. Code in `dashboard/` (bank), `dashboard/app/` (customer) and `scripts/serve_dashboard.py` (API). |
| B | Source code, with run instructions | `README.md` (run instructions); `src/gcip/` (library), `scripts/` (entry points), `configs/` (every rule, threshold and assumption), `tests/` (16 tests). |
| C | Trained models and inference code | Models in `demo/pipeline/models/`: `propensity_GP01.joblib` to `propensity_GP06.joblib` (five bootstrap LightGBM models plus an isotonic calibrator each), `thresholds.json`, and `categoriser.joblib` (rules, merchant lookup, TF-IDF linear model). Inference: `scripts/predict.py` (`propensity` scores a snapshot, `categorise` labels transaction text), built on `gcip.models.propensity.score_live` and `gcip.categorise.model.Categoriser`. Training: the `propensity` stage of `scripts/run_pipeline.py` and `scripts/build_model_inputs.py`. |
| D | Preprocessing pipeline | `scripts/build_full_data.sh`. It generates the synthetic bank (`gcip.simulate`), writes 7 source-system extracts, then runs FR1 ingestion with audit and 36 validation checks (`gcip.fr1.ingest`, `gcip.simulate.validate`), the warehouse and Customer 360 at two dates (`gcip.fr1.customer360`), the FR2 categoriser (`gcip.categorise`), point-in-time features (`gcip.features.store`) and take-up labels (`gcip.fr1.labels`). Documented in `docs/PIPELINE.md` section 3, `docs/DATA_CARD.md` and `docs/data_contract/`. |
| E | LLM implementation | `docs/LLM.md`: role, model and API (Gemini Flash; local Qwen2.5-1.5B offline), the prompts word for word, the guards, the evaluation approach and results. Code: `src/gcip/explain/` (`llm.py`, `guards.py`, `templates.py`, `run.py`); configuration in `configs/pipeline.yaml` `llm:`. |
| F | Architecture diagram | `docs/architecture/architecture.png`, also as `architecture.pdf` and its TikZ source `architecture.tex`; explained in `docs/EXPLAINER.md` section 9. |
| G | Evaluation report (validation set) | `docs/EVALUATION.md`: data splits, label generation, leakage controls, baselines and scenario tests. It reports FR3 propensity, fairness, the FR2 categoriser, FR4 truth recovery, FR5 explanations and the targeting backtest on validation, next to test. Generated by the `evaluate` stage: `demo/pipeline/metrics/evaluation_report.json` and `.md`. |
| H | Responsible AI note | `docs/RESPONSIBLE_AI.md`: privacy, bias and fairness, explainability, hallucination, human oversight, data limitations. |
| I | Test set predictions | `demo/pipeline/predictions/test_predictions.csv`: 12,073 rows, one per eligible test customer x product. Columns: `customer_id`, `product`, `opportunity`, `propensity`, `confidence`, `suggest` (clears the product's threshold), `rules_score`, and `took_up` (observed 1 Apr to 30 Sep 2026). Validation and test together: `heldout_predictions.csv`. Live suggestions for all 30,000 customers: `demo/pipeline/recommendations/recommendations.parquet`. |

Rebuild everything from source with `./run.sh --quick` (2,000 customers, about 3-5 minutes) or `./run.sh --rebuild`
(30,000 customers). Both write the models, predictions and evaluation report into `runs/`.
